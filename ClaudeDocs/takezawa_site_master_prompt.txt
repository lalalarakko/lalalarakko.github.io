## 0. 【最重要】作業の絶対ルール

### mdファイルについて
- **Claudeはmdファイルをスクラッチから生成しない**
- **先生が管理するmdファイルを丸ごと上書きしない**
- **先生から明示的に指示されていないmdファイルを変更しない**
- **JSONに存在しないデータをmdに書き込まない（ハルシネーション厳禁）**

### astroファイル・cssについて
- Claudeが担当するのは `.astro` ファイルと `global.css` のみ
- 修正依頼時は必ず現在のファイルを参照してから修正する（後述のワークフロー参照）
- スクラッチから書き直さない
- **ファイルを渡す際は必ず保存先パス（例: `src/layouts/BaseLayout.astro`）と、新規作成／既存ファイルを上書きの別を明示すること**

### 作業前の承認ステップ（必須）
1. Claudeは変更内容をテキストで先に説明する
2. 先生が「進めてください」と承認する
3. 承認後にファイルを修正・出力する

この承認ステップを省略してファイルを無断修正・上書きしてはならない。

### publications更新の正しい手順
1. 先生が **現在のmdファイル**（papers.md等）と**新しいJSONLファイル**の両方をアップロードする
2. JSONLのみアップロードされた場合、Claudeはmdを生成しない
3. ClaudeはJSONLと現在のmdを比較し、**差分（追加・変更分）のみ**を特定する
4. 差分を `papers_updates.md` 等の別ファイルとして出力する
5. 先生が内容を確認してから、手動で既存のmdに追記・修正する

### Claudeへの作業依頼時に必要なもの
- このマスタープロンプト
- 修正対象ファイルのGitHub raw URL（後述）または takezawa-site.zip
- 変更内容の説明

## 3. Claudeへのファイル渡し方（推奨ワークフロー）

### 推奨：GitHub raw URLで個別ファイルを渡す

リポジトリは公開されているため、Claudeがweb_fetchで直接取得できる。
毎回zipを作成・アップロードする手間がなく、コンテキストも最小化される。

チャットに以下のURLを貼るだけでよい：

```

https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/pages/index.astro
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/pages/publications.astro
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/pages/research.astro
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/pages/cv.astro
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/layouts/BaseLayout.astro
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/styles/global.css

# contentファイル（差分確認時など）
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/content/lab/alumni.md
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/content/lab/theses.md
https://raw.githubusercontent.com/lalalarakko/lalalarakko.github.io/main/src/content/publications/papers.md
```

### 標準ワークフロー

1. 先生がチャットにマスタープロンプト＋raw URLを貼る
2. ClaudeがURLをfetchして現状を把握し、変更計画をテキストで先に説明する
3. 先生が「進めてください」と承認する
4. Claudeが修正ファイルを出力（保存先パスを明示）
5. 先生がローカルに保存 → ローカル確認 → git push

### 代替：zipをアップロードする（従来方式）

複数ファイルをまとめて渡したい場合や、公開前の変更が含まれる場合に使用。

```bash

  --exclude "*/node_modules/*" \
  --exclude "*/.git/*" \
  --exclude "*/dist/*" \
```

## 6. Astro実装の重要ルール

### scriptタグ
- すべての<script>タグに is:inline 属性が必須
- TypeScriptの型注釈をscriptタグ内に書いてはならない

### set:htmlのCSSスコープ問題
- set:html で動的生成した要素にはscopedなCSSが当たらない
- 必ず :global() を使う

### noindexプロップ（BaseLayout.astro）
```typescript
interface Props { title: string; activePage?: string; noindex?: boolean; }
const { title, activePage = '', noindex = false } = Astro.props;
```
現在 noindex={true} を指定しているページ: lab.astro のみ

## 9. GitHub Actions設定

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist/
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

GitHub Settings → Pages → Source を GitHub Actions に設定。
デフォルトブランチは main（masterではない）。

## 10. トラブルシューティング

### JavaScriptが動かない
→ <script> タグに is:inline が付いているか確認

### YAMLエラー
→ 文字列値をシングルクォートで囲む
→ 文字列内のシングルクォートは '' でエスケープ

### git cloneで古いサイトが取得される
→ GitHub Settings → Default branch → main に設定
→ masterブランチは削除済み
