Section 01

新しいMacの環境構築

オフィスのMacなど、一度も作業したことのない新しいMacでの初回セットアップ手順です。

Step 1 — Node.js をインストール

1

Node.jsのダウンロード

ブラウザで https://nodejs.org を開き、LTS版をダウンロードしてインストールします。

node -v
# v20.x.x のような表示が出ればOK

Step 2 — Gitの設定

2

ターミナルを開く（Spotlight: Command + Space → "Terminal"）

git config --global user.name "Masanori Takezawa"
git config --global user.email "your@email.com"

このMacで1度だけ実行すればOKです。

Step 3 — GitHubのPersonal Access Tokenを確認

3

トークンの準備（ghp_で始まる文字列）

紛失した場合は再作成：GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)

Scope: repo と workflow にチェック。Expiration: No expiration。

Step 4 — リポジトリをクローン

4
mkdir ~/GitProjects
cd ~/GitProjects
git clone https://github.com/lalalarakko/lalalarakko.github.io.git takezawa-site

ユーザー名・パスワードを求められたら：Username: lalalarakko / Password: Personal Access Token

注意

パスワード欄は入力しても何も表示されません。正しく入力されているのでそのままEnterを押してください。

Step 5 — パッケージをインストール

5
cd ~/GitProjects/takezawa-site
npm install

warningやvulnerabilityの警告は無視して問題ありません。

完了

この手順はこのMacで最初の1回だけ必要です。次回からは git pull するだけでOKです。

Section 02

ローカルでの動作確認（localhost）

開発サーバーの起動

cd ~/GitProjects/takezawa-site
npm run dev

ブラウザで http://localhost:4321 を開くとサイトが表示されます。

ホットリロード

src/content/ 以下のMarkdownファイルを編集・保存すると、ブラウザが自動的に更新されます。

開発サーバーの停止

ターミナルで Control + C を押して停止します。

よくあるエラー

エラー対処
YAMLExceptionMarkdownファイルの書き方が間違っています。文字列をシングルクォートで囲んでいるか確認してください。
Cannot find modulenpm install を実行してください。
ポート4321が使用中Astroが自動的に別のポートを使います。ターミナルに表示されたURLを確認してください。

Section 04

Claudeへの修正依頼方法

原則

Claudeはmdファイルをスクラッチから生成・上書きしません。Claudeが担当するのは .astro ファイルと global.css のみです。

astroファイルの修正を依頼する場合

以下をすべてClaudeに添付して依頼します：

  1. マスタープロンプト（takezawa_site_master_prompt.txt）
  2. 最新の takezawa-site.zip（下記コマンドで作成）
  3. 変更内容の説明

takezawa-site.zip の作成方法

修正依頼前に、以下のコマンドで最新のサイトをzip圧縮してClaudeにアップロードします。定期的にアップロードすることで、Claudeが常に最新のファイルを参照できます。

cd ~/GitProjects
zip -r takezawa-site.zip takezawa-site \
  --exclude "*/node_modules/*" \
  --exclude "*/.git/*" \
  --exclude "*/dist/*" \
  --exclude "*/.astro/*"

推奨

Claudeに修正を依頼するたびに最新のzipをアップロードしてください。これにより、Claudeが古いバージョンのファイルを上書きしてしまうリスクを防ぎます。

Publications差分の確認を依頼する場合

  1. マスタープロンプト
  2. publications_generation_prompt.txt
  3. 現在の最新mdファイル（papers.md等）← 必須
  4. 新しいJSONLファイル ← 必須
  5. 「差分のみを出力せよ」と指示

重要

mdファイルとJSONLファイルの両方をアップロードしてください。JSONLのみの場合、Claudeはmdを生成しません。Claudeが出力するのは差分（papers_updates.md等）のみです。内容を確認してから手動で既存のmdに追記してください。

Section 05

コンフリクト（競合）への対応

Mac Aで作業した後、git pullせずにMac Bで同じファイルを編集してしまった場合に発生します。

コンフリクトが発生したとき

CONFLICT (content): Merge conflict in src/content/publications/papers.md
Automatic merge failed; fix conflicts and then commit the result.

対処法A — 自分の変更を優先する（推奨）

git checkout --ours src/content/publications/papers.md
git add src/content/publications/papers.md
git commit -m "Resolve conflict: keep local version"
git push

対処法B — GitHubの版を優先する

git checkout --theirs src/content/publications/papers.md
git add src/content/publications/papers.md
git commit -m "Resolve conflict: keep remote version"
git push

対処法C — すべてをリセット

# ⚠️ ローカルの未保存変更がすべて消えます
git fetch origin
git reset --hard origin/main

現在の状態を確認する

git status          # 変更されたファイルの一覧
git diff            # 変更内容の詳細
git log --oneline -10   # コミット履歴
